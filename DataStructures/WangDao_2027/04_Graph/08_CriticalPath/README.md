# 关键路径（Critical Path）学习示例

本目录包含一个自包含的 C++ 示例程序 `critical_path_learning.cpp`，用于学习工程网络中的关键路径问题（AOE 网络）。

程序提供以下内容：

- 邻接矩阵版关键路径计算
- 邻接表版关键路径计算
- 中文注释与逐步输出
- 关键边判定（slack 为 0 的边）
- 最早开始时间（earliest）与最晚开始时间（latest）

---

## 1. 什么是关键路径

关键路径是指在一个工程网络中：

- 顶点表示事件（事件发生的时刻）
- 有向边表示活动（活动的持续时间）
- 边权表示活动持续时间

关键路径上的活动被称为关键活动，关键活动的“松弛量（slack）”都为 0，表示它们不能延迟，否则整个项目工期会延长。

在 AOE 网络中，关键路径的长度等于项目的总工期。

---

## 2. 关键路径的核心思想

关键路径问题本质上是：

1. 对网络做拓扑排序；
2. 计算每个顶点的最早发生时间 `earliest[u]`；
3. 计算每个顶点的最晚发生时间 `latest[u]`；
4. 对每条边 `(u, v)` 计算：

```
slack = latest[v] - earliest[u] - weight(u, v)
```

如果 `slack == 0`，则这条边是关键边；
所有关键边连接起来，就形成关键路径。

---

## 3. 程序中的示例网络

本程序构造了一个 7 个顶点的工程网络：

- `0 -> 1 (3)`
- `0 -> 2 (4)`
- `1 -> 3 (5)`
- `1 -> 4 (6)`
- `2 -> 3 (8)`
- `2 -> 5 (7)`
- `3 -> 4 (3)`
- `3 -> 6 (9)`
- `4 -> 6 (4)`
- `5 -> 6 (2)`

这个图是一个 DAG（有向无环图），因此可以计算关键路径。

实际关键路径为：

```
0 -> 2 -> 3 -> 6
```

对应工期：

```
4 + 8 + 9 = 21
```

---

## 4. 关键路径与拓扑排序的关系

关键路径算法通常基于拓扑排序：

- 先用拓扑排序求出一个合法的处理顺序；
- 然后从前往后计算 `earliest`；
- 再从后往前计算 `latest`；
- 最后判断哪些边的 slack 为 0。

这说明：

- 关键路径依赖图的 DAG 结构；
- 拓扑序是关键路径计算的基础；
- 关键路径本质上是“最长路径”，而不是最短路径。

---

## 5. 邻接矩阵和邻接表的区别

### 邻接矩阵

- 适合中等规模稠密图
- 访问某条边 `u -> v` 非常快
- 可以直接用二维数组判断连通关系
- 代码更直观，便于教学演示

### 邻接表

- 更适合稀疏图
- 空间占用更小
- 在真实工程中更常用
- 更接近实际项目代码实现方式

## 9. 学习建议

建议按下面顺序学习：

1. 先理解 AOE 网络：顶点是事件、边是活动
2. 再掌握拓扑排序：为关键路径计算准备序列
3. 再理解 `earliest`：从前往后计算最早完成时间
4. 再理解 `latest`：从后往前计算最晚允许时间
5. 最后看 slack：为 0 的边就是关键边
