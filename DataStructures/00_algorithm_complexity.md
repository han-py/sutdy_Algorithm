# 算法的时间复杂度与空间复杂度
这份文档用于系统学习和复习算法中的**时间复杂度**与**空间复杂度**，帮助你在写代码、刷题和面试时快速判断一个算法的效率。
---
## 1. 什么是复杂度？
复杂度用来衡量算法在**输入规模增大**时，运行时间和额外内存消耗的增长趋势。
- **时间复杂度**：算法执行所需时间随输入规模 `n` 增长的变化趋势。
- **空间复杂度**：算法运行过程中额外占用内存随输入规模 `n` 增长的变化趋势。
> 复杂度关注的是“趋势”，不是具体执行秒数。
---
## 2. 为什么要学习复杂度？
学习复杂度的意义主要有：
1. **比较算法优劣**：同样完成一个任务，不同算法的效率可能差很多。
2. **预测性能瓶颈**：输入变大后，哪些程序会变慢、会占多少内存。
3. **指导代码设计**：避免写出低效的循环嵌套或大量重复计算。
4. **面试必考**：几乎所有算法题都会要求分析复杂度。
---
## 3. 时间复杂度
### 3.1 常见表示法
时间复杂度通常使用 **大 O 表示法**（Big-O）描述。
- `O(1)`：常数时间
- `O(log n)`：对数时间
- `O(n)`：线性时间
- `O(n log n)`：线性对数时间
- `O(n^2)`：平方时间
- `O(2^n)`：指数时间
- `O(n!)`：阶乘时间
### 3.2 从小到大的增长关系
一般来说：
`O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(2^n) < O(n!)`
越靠前，通常越高效。
---
## 4. 常见时间复杂度示例
### 4.1 `O(1)`：常数时间
不管输入规模多大，执行次数基本不变。
```cpp
int x = a[0];
```
**解释**：只访问一次数组元素。
---
### 4.2 `O(log n)`：对数时间
每次操作都把问题规模缩小一半。
典型例子：**二分查找**。
```cpp
int binarySearch(vector<int>& nums, int target) {
    int l = 0, r = nums.size() - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) l = mid + 1;
        else r = mid - 1;
    }
    return -1;
}
```
**解释**：每次把搜索范围减半，所以复杂度是 `O(log n)`。
---
### 4.3 `O(n)`：线性时间
执行次数与输入规模成正比。
```cpp
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```
**解释**：循环执行 `n` 次。
---
### 4.4 `O(n log n)`：线性对数时间
常见于高效排序算法。
典型例子：**归并排序、快速排序（平均情况）**。
```cpp
// 归并排序的整体复杂度通常为 O(n log n)
```
**解释**：递归层数是 `log n`，每层处理 `n` 个元素。
---
### 4.5 `O(n^2)`：平方时间
通常出现在双重循环中。
```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        // do something
    }
}
```
**解释**：外层 `n` 次，内层 `n` 次，总共 `n * n = n^2` 次。
---
### 4.6 `O(2^n)`：指数时间
每增加一个元素，问题规模会成倍增长。
典型例子：暴力枚举子集、部分递归暴力搜索。

**解释**：增长非常快，n 稍大就难以运行。
---
### 4.7 `O(n!)`：阶乘时间
典型例子：暴力排列全排列问题。
```cpp

```
**解释**：增长极快，通常只用于理论分析或极小规模输入。

## 5. 如何分析时间复杂度？
### 5.1 关注“最坏情况”
大多数情况下，Big-O 记号表示**最坏情况**复杂度。
例如：
- 顺序查找：最坏情况 `O(n)`
- 二分查找：最坏情况 `O(log n)`
### 5.2 只保留最高阶项
例如：
- `O(3n + 5)` → `O(n)`
- `O(n^2 + n + 10)` → `O(n^2)`
- `O(2n log n + 100n)` → `O(n log n)`
### 5.3 忽略常数系数
例如：
- `O(2n)` → `O(n)`
- `O(100n)` → `O(n)`
因为当 `n` 很大时，常数影响相对较小。
### 5.4 多层循环相乘
如果是嵌套循环，通常把每层复杂度相乘。
```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        // O(n * m)
    }
}
```
### 5.5 顺序执行相加，嵌套执行相乘
- 顺序写的多个代码段：复杂度相加
- 嵌套循环：复杂度相乘
例如：
```cpp
for (int i = 0; i < n; i++) { }
for (int j = 0; j < n; j++) { }
```
复杂度是 `O(n + n)`，即 `O(n)`。
---
## 6. 空间复杂度
空间复杂度表示算法运行过程中，**额外**使用的内存空间随输入规模变化的趋势。
### 6.1 注意“额外空间”
空间复杂度通常不包括输入本身所占空间，只统计辅助空间。
例如：
- 输入数组本身是题目给定的，不算额外空间
- 新建一个同样大小的数组，就会增加空间复杂度
### 6.2 常见空间复杂度
#### `O(1)`：常数空间
只使用固定数量的变量。
```cpp
int a = 0, b = 1, c = 2;
```
#### `O(n)`：线性空间
额外使用与输入规模成正比的空间。
```cpp
vector<int> temp(n);
```
#### `O(log n)`：对数空间
常见于递归调用栈，例如二分递归。
---
## 7. 时间复杂度和空间复杂度的关系
有时候，时间和空间需要权衡：
- 用更多空间换更少时间
- 用更少空间换更多时间
### 例子：哈希表
- 使用哈希表可以把查找从 `O(n)` 降到平均 `O(1)`
- 但需要额外的空间存储映射关系
### 例子：动态规划
- 朴素递归可能时间复杂度很高
- 记忆化搜索或 DP 可以用更多空间换取更快的时间
---
## 8. 常见算法复杂度速查表
| 算法/操作 | 时间复杂度 | 空间复杂度 |
|---|---:|---:|
| 数组访问 | `O(1)` | `O(1)` |
| 线性查找 | `O(n)` | `O(1)` |
| 二分查找 | `O(log n)` | `O(1)` |
| 冒泡排序 | `O(n^2)` | `O(1)` |
| 选择排序 | `O(n^2)` | `O(1)` |
| 插入排序 | `O(n^2)` | `O(1)` |
| 归并排序 | `O(n log n)` | `O(n)` |
| 快速排序（平均） | `O(n log n)` | `O(log n)` |
| BFS/DFS | `O(V + E)` | `O(V)` |
| 哈希表查找 | 平均 `O(1)` | `O(n)` |
> `V` 表示顶点数，`E` 表示边数。

## 9. 递归复杂度分析
递归题目常见分析方式有两种：
1. **递归树法**
2. **主定理**
### 9.1 递归树法
例如：
```cpp
T(n) = 2T(n/2) + O(n)
```
这通常对应归并排序。
- 每一层总工作量是 `O(n)`
- 递归深度是 `O(log n)`
- 所以总复杂度是 `O(n log n)`
### 9.2 主定理
对于形式：
```text
T(n) = aT(n/b) + O(n^k)
```
可以用主定理快速判断复杂度。
如果你刚开始学习，可以先掌握递归树法，再逐步学习主定理。
---
## 10. 分析复杂度的实用步骤
当你看到一个算法时，可以按下面步骤分析：
1. 看有没有**循环**
2. 看有没有**嵌套循环**
3. 看循环次数是否会递减、减半或跳跃
4. 看有没有**递归**
5. 只保留**最高阶**项
6. 区分**时间**和**额外空间**
---
## 11. 常见误区
### 误区 1：把 `O(n)` 误认为“最多执行 n 次”
实际上，`O(n)` 只表示增长趋势，不是精确次数。
### 误区 2：忽略递归栈空间
递归函数除了时间复杂度，还要考虑调用栈空间。
### 误区 3：把输入空间也算进空间复杂度
通常只统计额外空间，不算输入本身。
### 误区 4：看到循环就直接判断为 `O(n^2)`
要看循环是否嵌套，以及每层循环的范围如何变化。
---
## 12. 学习建议
1. 先掌握 `O(1)`、`O(n)`、`O(log n)`、`O(n^2)`
2. 熟悉常见排序和查找算法的复杂度
3. 多练习递归题，理解递归树
4. 写代码时养成“边写边分析复杂度”的习惯
5. 遇到题目时，先想有没有更低复杂度的解法
---
## 13. 一页记忆版
- **时间复杂度**：程序跑得有多快
- **空间复杂度**：程序占多少额外内存
- **Big-O**：描述增长趋势
- **常见等级**：`O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n^2)`
- **原则**：只保留最高阶项，忽略常数

## 15. 总结
算法复杂度是理解程序效率的核心工具。
- 时间复杂度关注运行速度
- 空间复杂度关注额外内存
- 分析时要抓住循环、递归、嵌套和数据结构开销
- 学会复杂度分析后，你会更容易写出高效、可扩展的代码
